# DATA_MANIFEST — binaries not tracked in git

`flood-v4.0` is **self-contained on disk** but the heavy binary inputs are kept out of git
(per the consolidation decision: lean history, ship binaries via the Zenodo archive). A fresh
`git clone` must be paired with the data archive staged over the working tree. This file lists
what is gitignored and where it came from.

## Gitignored patterns (see `.gitignore`)

| Pattern | What it covers | Provenance |
|---|---|---|
| `*.tif`, `*.tiff` | All rasters: bare-earth DEMs, HANDs, KL raingrid DEM, Bangkok de-biased/defended DEM + polder mask, masks (sea/river/runoff), copernicus DSM baseline, DEM QA | Built in `flood-v3.0/dem/` (DEMs) and `flood-v2.0` (masks, HANDs); see below |
| `*.zip` | Flood-observation source archives (DFO Dartmouth, GFM/Sentinel-1, ARIA) | Public flood-obs repositories; download URLs in each `data/<city>/flood_obs/*/` |
| `outputs/`, `cache/`, `logs/`, `*.log` | Regenerable atlas outputs and scratch | Regenerated by `repro/run_all.ps1` |

Kept in git (the lean-provenance payload): all `*.py`, `*.tex`, `*.md`, `*.csv`, `*.json`,
`*.parquet` (calib + ICESat-2/GEDI ground-truth points), `*.shp`/`*.dbf`/`*.shx` vector obs,
`*.yml`, hazard-forcing CSVs, and the registers.

## Not vendored (re-downloadable; documented, not copied)

Per the lean-provenance decision, the DEM-build **source** rasters are *not* in `flood-v4.0`.
To rebuild a DEM from scratch (vs. using the vendored conditioned DEMs), fetch:

- **Copernicus GLO-30 DSM** — <https://spacedata.copernicus.eu/> (per-city tiles).
- **ICESat-2 ATL08 / GEDI L2A** ground returns — the sampled points are vendored as
  `dem/<city>/ground_truth/*.parquet` (enough to re-derive calibration); the raw granules are
  re-fetchable via `dem/fetch_ground_truth.py`.
- **ETH GlobalCanopyHeight 10 m 2020** — ETH ownCloud mirror (KL tiles N03E099 + N00E099).
- **DeltaDTM** (Singapore) — the published ≤30 m bare-earth product.
- The original `flood-v3.0/dem/<city>/{auxdata,cache}/` intermediates (~6 GB) are regenerable
  and intentionally left behind.

The per-city DEM calibration (`dem/<city>/calib/calibration.json`, never reused across cities)
and held-out validation (`dem/<city>/dem_validation_*.json`) are vendored, so the §8.1 accuracy
table and the calibration are fully reproducible from this repo.
